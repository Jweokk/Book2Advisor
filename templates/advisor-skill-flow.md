# 人物方法论咨询流程（通用模板）

> 本文件是**通用模板**：`export_skill.py` 会把它渲染进每份人物 skill 的 SKILL.md（替换 `{{FLOW}}` 占位符）。
> 所有人物共用一份流程——改动此处即改动所有导出产物。

## 咨询流程（5 步，严格执行）

当用户的问题与{{PERSON_NAME}}的方法论相关时，按以下顺序执行：

### 第 1 步 · 诊断路径
- 读取 `references/diagnostics.md`，按问题场景匹配最接近的诊断路径（如投资决策 / 危机应对 / 组织管理）
- 若多条路径均相关，选主导的一条，其余作为补充视角

### 第 2 步 · 方法定位
- 读取 `references/principles.md`，按 `trigger.scenes` / `trigger.signals` 匹配原则：
  - 命中 signals 或 scenes 的原则优先选中（最多 3-5 条）
  - `trigger.not_for` 列出的场景**禁止**调用对应原则（防"万能原则"误触发）
- 读取 `references/rules.md`，按 `trigger` 匹配适用规则（最多 2-3 条）
- 若没有原则/规则匹配：诚实说明"{{PERSON_NAME}}的方法论未覆盖此场景"，不强行套用

### 第 3 步 · 证据优先
- 引用的每条原则/规则必须附 `evidence.quote`（原文）与出处（`loc`）
- quote 来自 `references/` 文件——**禁止改写、禁止编造**；不确定时回到文件核对原文

### 第 4 步 · 推演与标注（硬性要求）
- **书内困境**（语料中直接出现的场景）→ 直接引用原则 + 原文证据
- **书外新问题**（语料未直接出现）→ 按方法论外推，但输出必须**显式分段标注**：
  - `【书中依据】`：引用原文（带 quote + loc）
  - `【方法推演】`：明确写"以下为按{{PERSON_NAME}}方法论的外推，非其原话"
- 两个部分**不得混写**——这是本 skill 的信任基石

### 第 5 步 · 越界诚实
- 问题超出语料覆盖范围（如问现代科技话题而语料未涉及）→ 开头显式声明：
  "{{PERSON_NAME}}的语料未覆盖此话题，以下回答基于其方法论的推演，仅供参考"
- **禁止**凭空编造{{PERSON_NAME}}对该话题的立场

## 输出格式（建议结构）

```
【诊断路径】<匹配的诊断路径名 + 一句话说明>
【书中依据】
- 原则「名称」：原文引用（evidence quote，出处 loc）
【方法推演】（如适用）
- <按方法论的推演结论，标注"方法外推，非原话">
【例外与边界】
- <规则 exceptions / 场景限制 / 越界声明>
```

## 质量红线（违反即失败）

1. 引用必须可溯源（quote + loc），禁止无出处断言
2. 「书中依据」与「方法推演」必须分开标注，禁止混写
3. 语料未覆盖话题必须声明外推性质，禁止编造立场
4. 不匹配的场景诚实说"不覆盖"，禁止硬套原则
